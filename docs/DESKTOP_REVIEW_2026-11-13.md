# v0.2.2 桌面化复查与第一批改进

基线：发布标签 v0.2.2，提交 cd750a9ec6912a30e1574994f079b9e6f2585b73。修改仅在本地，未发布安装包、未推送远程。

## 判断

项目已有桌面软件基础：pywebview 原生窗口、独立计算进程、SQLite、Windows 安装与卸载脚本。HTML/CSS 作为嵌入式界面不妨碍成为桌面软件。建议继续保留 Python 科研计算能力，先完善桌面生命周期、数据可靠性和环境诊断，暂不整套重写成 Qt 或 Electron。

本轮检查了入口、运行时、HTTP 服务、文件路径与预览、SQLite、执行退出、构建配置及测试；不是全部代码的形式化安全审计。

## 已修改

- 增加源码 `--desktop` 模式，Windows 启动脚本进入桌面模式；保留浏览器开发入口，互斥参数防止启动意图冲突。
- 保存关闭前的窗口位置和大小。配置损坏或移除外接屏幕时回到默认窗口，写入失败不会阻止退出。
- 本地 GET 接口拒绝浏览器明确标记的跨站请求，减少其他网页嵌入本地研究文件的机会。此检查不是用户认证，不能阻止同机进程。
- HTTP 连接增加 30 秒空闲读写超时，限制不完整请求长期保留线程；这不是 API 执行时长限制。
- 增加窗口配置、断开显示器与跨站文件请求回归测试。
- 增加 `scripts/smoke_window.py`：启动真实桌面窗口，等待前端 lumen_ready 后自动关闭。

## 验证

Windows / Python 3.14 / pywebview 6.2.1：真实 WebView2 加载前端成功，收到就绪信号后正常关闭。该检查不覆盖所有桌面交互和安装包升级。

完整 unittest 跑完 28 项，报告 4 个失败断言，均因本机缺少 Java、C/C++ 工具链：test_05、test_06 的两个子用例、test_16。未修改测试掩盖失败。新增测试、单实例启动、端口独占、Python 内核与取消、SSH 测试通过。详细输出见仓库本地 test-results/review-tests.txt。

最初在沙箱下测试出现临时目录及网络权限错误；正常权限复跑后这些错误消失。当前开发环境借用系统科学计算依赖，不可当作干净发布构建环境。尚未重建可分发 exe 或安装包。

## 下一阶段优先级与验收条件

1. **桌面实例生命周期**：当前重复启动可以给同一服务新开窗口，但主窗口关闭会终止共享服务，其他窗口可能断连。应改为向已有主窗口发送激活信号；验收为连续双击多次仅保留一个窗口，关闭后无服务或内核残留。
2. **任务退出与恢复**：Store 已把重启前运行任务标为 interrupted；这不等于断点续算。加入有运行任务时的关闭提醒、明确的取消状态与重跑入口；验收包含计算、AI 等待核对、远程命令三种退出情形。远程进程状态需要单独确认。
3. **环境管理**：Java 与编译工具缺失会让相关运行失败。先提供可操作的缺失项诊断、项目依赖锁定与安装日志；不要为每个项目直接修改软件内置 Python。使用干净 Python 3.11 环境重建并验证发布包。
4. **大表格交互**：files.table_preview 当前完整读取小于 32 MiB 的表后计算摘要，Parquet 也先全量读取。文件大小不代表解压后的内存用量；引入抽样预览、后台摘要和按列读取，并明确显示抽样范围。
5. **数据恢复**：SQLite WAL 已开启，但未形成可验证的自动备份与恢复流程。采用 SQLite backup API 制作一致性备份，再做迁移版本与恢复演练；不能直接复制正在写入的单个数据库文件充当完整备份。
6. **发布质量**：在干净 Windows 10/11 测试安装、升级、卸载保留研究数据、无 Python 环境计算；加入代码签名、更新校验与失败回滚，再进入稳定软件发布。

## 本地启动

双击仓库根目录“启动科研工作台.cmd”；已配置 .venv 的桌面依赖。手动启动为 `.venv\Scripts\python desktop.py --desktop`。窗口加载失败会显示诊断并允许选择浏览器；没有移除原来的应急入口。

正式打包仍按 docs/DESKTOP_BUILD.md；本轮没有改版本号或触发云端发布。
