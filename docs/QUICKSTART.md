# 从第一次打开开始

## 1. 打开工作台

Windows 普通用户可在 [Releases](https://github.com/zbyloveyj/LUMEN-Science/releases) 下载 x64 安装版，安装后打开桌面快捷方式；也可完整解压便携包，运行 LUMENScience.exe。内置 Python 与常用分析包，无需单独安装 Python。原生窗口关闭后会停止本实例服务，项目和设置保存在 `%LOCALAPPDATA%\LUMENScience`；卸载不删除研究资料。

源码用户在安装依赖后双击“启动科研工作台.cmd”，或运行 python run.py。源码方式使用本机浏览器；浏览器窗口关闭不会自动停止服务，再次启动会打开已有实例。源码默认数据目录仍为 .state。

命令行运行时可以按 Ctrl+C 停止；服务仅监听本机。默认端口被占用会选择新端口，不关闭其他程序。

如果独立窗口显示 `127.0.0.1` 连接超时，先关闭窗口，再从开始菜单打开 **LUMEN Science (Browser)**（0.2.1 起）。若浏览器仍无法连接，可在工作台启动时打开 `%LOCALAPPDATA%\LUMENScience\server.json`，在浏览器中访问其中的 `url`。独立窗口的加载问题见同目录的 `desktop-startup.log`，本机服务的启动错误见 `startup-error.log`。

从 0.2.2 起，侧栏的 **退出工作台** 会停止本机服务。在浏览器模式下，升级前也请先使用这个按钮。安装程序检测到旧版仍在运行时会提示先退出。

## 2. 先体验合成示例

示例项目包含120行固定随机种子生成的数据，不代表真实研究。

1. 打开“数据资源”，查看6个变量、缺失和数据预览。
2. 打开“多语言 Notebook”，运行第一个 Python 单元，随后运行第二个。
3. 打开“分析流程”，选择“数据质量体检”并运行。
4. 在“成果与溯源”查看图表、质量表和运行来源。
5. 点击某次运行的“独立重跑”，在新项目、新进程中检查自包含代码。
6. 打开“报告与交付”，生成分析记录并导出项目。

## 3. 选择语言

Notebook 的“添加单元”可选择十二种语言。页面展示工具检测状态；待配置的语言不能凭空运行。

- Python：所选环境需要 ipykernel。变量在本次内核生命周期内保留。
- R：自动寻找常见安装路径中的 Rscript；也可在设置中手动指定。Rscript 是独立进程，IRkernel 可持续计算。
- C/C++：需要 GCC、Clang 或可选 Zig；先编译，再执行生成的程序。
- Java：需要 JDK；示例入口类名为 Main。
- JavaScript/TypeScript：需要 Node.js；TypeScript 使用类型擦除，不支持所有 TypeScript 语法或构建工程。
- Go/Rust：需要本机对应编译器，当前按单文件编译。
- PowerShell/Bash：在相应 Shell 的独立进程执行。
- SQL：SQLite 数据库位于项目内部 .lumen/analysis.sqlite3；查询结果写入 outputs。

本地文件相对于当前项目根目录。请将图表、结果表写入 outputs，将可复用脚本写入 scripts。

Windows 上，R 和部分编译器不能处理带空格或非 ASCII 的工具路径。程序会将这类单文件编译/运行所需源码暂存到独立兼容目录，仍以原项目为工作目录，输入输出路径不变。默认选择系统临时目录；若本机临时路径也不兼容，可在设置中指定一个已有的无空格 ASCII 临时目录。原代码和成果记录仍保存在项目内。

## 4. 连接模型

填写服务商给出的 API 基础地址、模型 ID 和密钥，选择 Chat Completions 或 Responses 协议。点击“测试连接”后保存。模型支持与接口协议需要匹配。

讨论模式仅向模型提供读取工具；协作模式默认先核对代码或写入操作，再执行。本轮自动执行只影响当前消息。

本地文件组织不等于在线模型离线运行；发送给模型的消息和工具结果会通过配置接口传输。

## 5. 连接服务器

填写主机、端口、用户名、远程工作目录及明确指定的认证方式。首次检测显示服务器主机公钥指纹；请通过可信渠道核对，再保存连接。

通过“测试连接”检查 SSH 认证和 SFTP 工作目录。远程命令在该目录执行，每次是独立 Shell。SFTP 浏览和传输限制在所选目录中，不覆盖远端同名文件。

当前没有远程持续 Notebook 或交互式终端；需要多步共享状态时可以提交一个完整脚本或一条完整命令。取消只结束本次等待，不保证远端作业已经退出。

## 6. 正确理解复现

输入指纹证明当时记录的文件身份，不证明捕获所有实际读取。持续内核中的代码可能依赖旧变量。

独立重跑创建新项目，只复制已声明且当前指纹仍一致的输入。缺失前处理、未声明输入或旧变量依赖会导致失败；应补齐脚本再检查。

运行通过与统计数值一致、研究设计合理、科学结论成立分别核查。应用不会自动将它们等同。
